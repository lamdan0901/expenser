# Expenser Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A passcode-gated personal expense tracker on Cloudflare Workers + D1: monthly Notion-style sheets, fast top-insert logging, fixed/recurring items, inline editing, drag-reorder, VND formatting.

**Architecture:** One Worker serves static assets (`public/`) and a JSON API under `/api/*`, with a D1 database. Frontend is vanilla JS (no framework), unit-tested pure modules plus DOM behavior verified via `wrangler dev` against the local D1. Backend logic is covered by integration tests through `@cloudflare/vitest-pool-workers` with `isolatedStorage` so auth/DB state is per-test.

**Tech Stack:** Wrangler 4, TypeScript worker, D1, Vitest + `@cloudflare/vitest-pool-workers`, vanilla ES modules.

**Spec:** `docs/superpowers/specs/2026-11-02-expenser-design.md`

## Global Constraints

- Fully on Cloudflare: Workers + D1 only. No other service, no external libs beyond dev tooling.
- Single user. Every `/api/*` route except `POST /api/passcode` and `GET /api/me` requires the signed cookie `expenser_auth`.
- Passcode is a Worker secret `PASSCODE` set at deploy; never stored in D1.
- Amounts are full-VND **integers** in the DB; UI input is thousands-scale (user types `500` → `500000`; ×1000 including initial balance). Display: `fmtVND(n) → "500,000 ₫"` (comma separators, no decimals, `₫` appended).
- Months are `ym` strings `'YYYY-MM'`. Entry `date` is ISO `'YYYY-MM-DD'` and must fall inside `ym`. Entries always belong to the sheet being viewed.
- New entries insert at the **top** (position = current MAX(position)+1 within their table+ym scope).
- Notes (`kind='note'`) never count in any sum. Sums: income = fixed_income + income; expense = fixed_expense + expense.
- Months materialize on first **write** only; `GET /api/month/:ym` never writes.
- Fixed snapshots: template edits refresh the current-and-future context only; past (`ym < current ym`) fixed-row edits are snapshot-local. `ym === current` edits update template + current snapshot.
- UI is dark Notion-like per `mockup.html` (repo root): green income, red `−` expense, `⠿` drag handles, inline `contenteditable` editing, Enter commits.
- D1 `amount`/balance values travel as JSON numbers (integers ≤ 2^53, VND scale is safe).

## Review Focus

- An entry logged with a date outside the open month (or malformed date/ym) must be rejected with HTTP 400, not silently stored → Task 7.
- A fixed-row edit in a past month must change only that month's copy and leave the template and current month untouched → Task 9.
- Direct `curl` to any protected API route without a cookie must get 401 and an empty-body shape, and an invalid passcode never sets a cookie → Task 2.
- Unlimited passcode guessing on the public URL: 10 consecutive failures key the IP out for 10 minutes → Task 3.
- A `GET /api/month/:ym` for a never-touched month must return virtual fixed rows and a computed preview without creating `months`/`fixed_rows` rows → Task 6.
- Composer input `0`, `abc`, `12.5`, or `>10^9` must not create nonsense amounts (reject non-integers after ×1000) → Task 7.

- Rules (spec, owner decisions #1): rows with `template_id` set follow the template; rows with `template_id = null` are month-local always.

  - `ym < current`: create → `template_id = null` local row; patch/delete → that month's row only. Template and other months untouched — **assert in test** that after patching a past month, `templates.amount` and the current month's snapshot are unchanged.
